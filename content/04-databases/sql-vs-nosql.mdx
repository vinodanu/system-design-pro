# SQL vs NoSQL

> **Difficulty:** Beginner → production engineering. **Goal:** Develop the intuition, understand implementation choices, and explain tradeoffs in interviews.

## 1. Why this matters

Databases make different tradeoffs in data modeling, consistency, query patterns and scaling.

## 2. Mental model

Relational databases support transactions and joins. Document stores group related data for common access paths. There is no universal SQL-versus-NoSQL performance winner.

## 3. Explore the concept

Sketch a small system with two clients and three backend nodes. Change one assumption (load, latency, or a server failure), then trace how the behavior changes. Explain what should remain correct and which metric will get worse.

## 4. Java / Spring Boot deep dive

JPA/Hibernate suits many transactional relational workloads; MongoDB can suit document-centric access. Measure query plans, indexes and transaction needs instead of picking from hype.

## 5. Production tradeoffs

Denormalization speeds some reads but complicates updates; flexible schema still requires schema governance.

## 6. Check your understanding

**Question:** When should you prefer a relational database?

**Answer:** When strong transactional integrity, relational constraints and flexible joins dominate your requirements.

## 7. Try it in a project

Build a small Spring Boot service that demonstrates this principle. Record a baseline (latency, throughput, correctness), change one variable, and compare the results. Document what your measurements actually prove rather than assuming a benchmark result.
