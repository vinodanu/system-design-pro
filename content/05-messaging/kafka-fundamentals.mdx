# Kafka: Topics, Partitions and Consumer Groups

> **Difficulty:** Beginner → production engineering. **Goal:** Develop the intuition, understand implementation choices, and explain tradeoffs in interviews.

## 1. Why this matters

Kafka is an append-only distributed event log that lets producers and consumers work independently.

## 2. Mental model

A topic has partitions with ordering within each partition. Consumers in one group divide partitions; different groups can process the same data independently.

## 3. Explore the concept

Sketch a small system with two clients and three backend nodes. Change one assumption (load, latency, or a server failure), then trace how the behavior changes. Explain what should remain correct and which metric will get worse.

## 4. Java / Spring Boot deep dive

Spring for Apache Kafka provides listeners and producers. Choose message keys to preserve per-entity ordering and design handlers for duplicate delivery.

## 5. Production tradeoffs

Offset commits and processing are separate operations; at-least-once handling needs idempotency. More consumers than partitions in one group do not increase parallelism.

## 6. Check your understanding

**Question:** Does Kafka guarantee ordering across an entire topic?

**Answer:** No, ordering is guaranteed within a partition, not across all partitions.

## 7. Try it in a project

Build a small Spring Boot service that demonstrates this principle. Record a baseline (latency, throughput, correctness), change one variable, and compare the results. Document what your measurements actually prove rather than assuming a benchmark result.
